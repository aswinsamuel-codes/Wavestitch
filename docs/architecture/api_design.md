# API Design (Phase 0.7)

Status: Proposed · Date: 2026-11-07 · Style: REST/JSON, OpenAPI 3.1 generated by FastAPI; TypeScript client generated for the web app.

## 1. Principles
| Principle | Rule |
|---|---|
| Versioning | URL major version `/v1`. Within a version, additive changes only. Breaking changes → `/v2`; old version gets `Deprecation` + `Sunset` headers and ≥ 6 months' notice [A] |
| Tenancy | Org taken from the path (`/v1/orgs/{org_id}/…`) **or** from the `X-Org-Id` header for shorter asset routes; always verified against membership |
| Auth | `Authorization: Bearer <JWT>` (users) or `Bearer aos_live_…` (API keys, P2, scoped). Public share routes use the share token + optional passphrase session |
| Pagination | Cursor-based: `?limit=50&cursor=…` → `{ data: [...], next_cursor }` |
| Idempotency | `Idempotency-Key` header required on POSTs that create uploads, start jobs or touch billing; stored 24 h |
| Errors | RFC 9457 Problem Details: `{ type, title, status, detail, instance, code, errors[] }` |
| Rate limits | Per user and per API key; `RateLimit-*` headers (IETF draft) [K]; 429 with `Retry-After` |
| Long operations | Return `202 Accepted` + a job resource; progress over SSE `/v1/events` |
| IDs | UUIDs as strings; timestamps RFC 3339 UTC |

## 4. Webhooks (P2)
Events: `asset.ready`, `asset.failed`, `comment.created`, `version.approved`, `share.viewed`. Signed with `HMAC-SHA256` over `timestamp.payload` (`AOS-Signature` header); retries with exponential backoff for 24 h; delivery log visible to admins.
